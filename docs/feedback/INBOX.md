# INBOX.md — 사용자 피드백 / 최우선 지시

이 파일은 사용자(설계자)가 AI에게 남기는 지시와 피드백을 담는다.
**매 이터레이션 시작 시 가장 먼저 읽고, 다른 무엇보다 최우선으로 반영한다.**

## 사용 규칙

- 새 지시는 "남은 이슈 (미처리)" 섹션 맨 위(가장 최근이 위)에 날짜와 함께 추가한다.
- AI가 항목을 반영했으면 지우지 말고 `[처리됨 - YYYY-MM-DD]` 를 앞에 붙여 표시하고,
  **반드시 실제로 해당 섹션("처리됨" 또는 "부분 처리됨")까지 옮긴다** — 태그만 붙이고
  "남은 이슈" 섹션에 그대로 두지 말 것. (히스토리를 남겨야 나중에 "이 결정이 왜
  이렇게 됐는지" 추적 가능. 2026-09-09에 태그만 붙고 이동을 안 해서 몇 개가 계속
  "남은 이슈"에 남아있던 사고가 있었음 — 반복하지 말 것.)
- 처리 못 하거나 애매한 항목은 `docs/STATUS.md`의 "알려진 이슈 / 막힌 것"에 사유를 남기고,
  이 파일의 항목 앞에 `[보류 - 사유]`를 붙인다.
- 세 섹션 안에서는 각각 날짜 최신순(위쪽이 최근)으로 정렬한다.
- **"처리됨" 섹션이 12개를 넘으면**, 가장 오래된 항목들을(12개가 될 때까지) 잘라서
  `docs/INBOX_ARCHIVE.md` 맨 위에 옮겨 적어라(파일 없으면 새로 만들 것). 내용을
  요약하거나 버리지 말고 그대로 옮기기만 한다 — 이 파일은 매 이터레이션 통째로 읽는
  파일이라 계속 누적되면 읽기 비용이 무한정 커진다(STATUS.md가 2026-09-07에 275KB까지
  불어나 docs/STATUS_ARCHIVE.md로 정리한 것과 같은 이유). "부분 처리됨"은 여전히
  진행 중인 항목으로 취급해 archive하지 않는다.

    표로 정리해 둘 것 — 완료 후 감독이 "ProjectD Art"에 전달한다(새 모티프를 만들었다면 그 모티프 디자인 방향도).

  **N-6. 캐릭터 전용 이벤트 + 캐릭터 특별 선택지(잠금 노출) — 이벤트 판정(N-5(b)) 데이터 표/공용 함수 위에서 진행** (사용자 아이디어 2026-10-15)
  - 목적: "다음에 이 이벤트가 나오면 그 캐릭터로 하고 싶다"는 재방문 동기. 두 종류:
    ① **캐릭터 전용 이벤트**: 그 캐릭터로 플레이할 때만 이벤트 풀에 등장(다른 캐릭터는 절대 못 만남).
    ② **특별 선택지가 있는 이벤트**: 모든 캐릭터에게 같은 이벤트가 나오지만 선택지 중 하나가 특정 캐릭터 전용이다. **다른 캐릭터에게는 선택지가 "잠김"으로 보이되
       "○○(캐릭터명) 선택 가능"이라고 누가 열 수 있는지 명시하고, 그 선택지가 주는 효과 설명도 흐리게 보여준다(유혹이 목적이니 내용을 가리지 말 것).** 해당 캐릭터는 활성화되며
       **같은 계열의 일반 선택지보다 이득이 분명히 더 크다**(예: 보상 1.5~2배 또는 추가 효과 한 가지).

    **이벤트별/캐릭터별 하드코딩 금지** — 데이터 표 + 공용 처리 함수(순수 함수: "이 캐릭터에게 이 이벤트가 풀에 들어가나", "이 선택지의 상태(활성/잠김)와 최종 보상은?")로 만들어 `dice_test`가
    UI 없이 검증할 수 있게(N-5(b)의 판정 함수 방식과 같은 패턴).
  - 이벤트 풀 선택: 특수 이벤트 방에서 전용 이벤트가 너무 드물면 의미가 없으니, 전용 이벤트가 있는 캐릭터는 특수 이벤트 방에서 일정 확률(제안 20~30%, 상수로 분리)로 전용 이벤트로 대체되게 한다.
    결정은 기존 이벤트 선택과 같은 결정적 RNG(`run_seed` + 방 번호)를 써서 재현 가능해야 한다. 테스트 전투/QA 시드에서도 동작 확인.
  - 분량(최소): **전용 이벤트 4종 이상**(서로 다른 4명 이상의 캐릭터), **특별 선택지가 있는 이벤트 4종 이상**. 결과적으로 **현재 캐릭터(곡예사 포함 8명) 각각이 최소 1개의 전용 이벤트 또는 특별 선택지를
    가지게** 한다. 컨셉 예시(바꿔도 됨): 해적 — 보물 지도 전용 이벤트 / 광전사·폭발병 — 대장간·화약고 특별 선택지 / 수호자·주술사 — 신전 제단 특별 선택지 / 곡예사 — 서커스 단장 전용 이벤트(이벤트 주사위 대성공 연동) /
    매혹사 — 사교 파티 특별 선택지. 각 선택지의 효과는 기존 보상 체계(골드, 눈금, 다이스, 스킬, 체력)를 쓰고 전투 밸런스를 깨지 않는 범위에서 정의.
  - UI: 이벤트 화면의 잠긴 선택지는 퍼스널 컬러/자물쇠 아이콘(`resources/ui/icon/lock.png`)과 "🔒 ○○ 선택 가능" 문구 + 흐린 효과 설명으로 표시(UIKit 버튼 스타일 사용). 방향키 포커스는 잠긴 선택지에도 갈 수 있게 하고
    (왜 못 누르는지 알려주는 짧은 안내 문구), Space를 눌러도 실행되지 않는다. 해당 캐릭터에게는 선택지가 "○○ 전용"이라는 작은 배지와 함께 활성화되어 눈에 띄게 한다. 전용 이벤트는 이벤트 제목 옆에 전용 배지.
  - 도감 연계(선택, 이번 조각에서는 데이터만): 한 번 본 전용/특별 선택지를 영구 기록해 두면 나중에 "이벤트 도감" 조각에서 쓸 수 있게 `SkillCodex`와 같은 패턴으로 저장 훅만 준비해도 좋다(테스트 전투 제외).
  - 테스트(계산/동작 결과): 전용 이벤트가 소유 캐릭터에게만 풀에 들어가는지(다른 7명은 시드 100개에서 0회, 소유자는 기대 확률 범위), 특별 선택지가 비소유 캐릭터에서 잠김 상태이고 실행 시도해도 상태가 안 바뀌는지,
    소유 캐릭터의 최종 보상이 일반 선택지보다 실제로 큰지(수치 비교), 8명 전부 최소 1개의 전용/특별 콘텐츠를 가지는지. qa_shot으로 잠긴 선택지/활성 특별 선택지/전용 이벤트 화면을 눈으로 확인(셀프 피드백).

  던전 순환에 바로 영향을 줘 범위가 커서 G-6(던전 순환 로직 자체를
  "런 몬스터 계획"으로 교체하는 단계)으로 미뤘다(이유 상세는
  `monster_catalog.gd` 상단 주석). G-1~G-4까지는 지시대로 "전투 동작을
  바꾸지 않는다"를 지켜 기존 dice_gimmick 적용 로직/스케일링 공식/로그
  문구(수치)가 전혀 안 바뀌었다(G-3/G-4가 만든 12종은 그때까지 아무 몬스터도
  안 써서 전부 no-op) — 다만 G-4 작업 중 "몬스터 공격턴 값 보정은 데미지
  계산 전에 호출해야 실제 반영된다"는 잠재 버그를 발견해 고치면서, anger_
  stack 관련 로그("분노 스택 ...") 한 줄의 출력 **순서**만 데미지 로그보다
  앞으로 바뀌었다(수치는 그대로). G-5는 신규 16종에 한해 처음으로 "실제
  동작하는" 몬스터 데이터를 만들었지만, 던전 순환 자체는 여전히 기존 5종만
  쓰도록 `legacy_cycle_monster()`로 호환을 지켜(동작 보존) 신규 16종은
  G-6 전까지 `GAME_QA_MONSTER_ID` QA 훅으로만 확인 가능하다. `dice_test.gd`의
  신규 검증(각 단계별)으로 room 0~9 전부에서 기존과 동일한 결과가 나오는지
  + G-3/G-4 12종의 계산 결과(게이팅, 1회 제한, 동시 적용 시 중복 집계
  없음 포함) + G-5 카탈로그 규모/신규 프리미티브 적용 결과(amount
  파라미터가 실제 계산값을 바꾸는지)까지 확인했다. 다음은 **G-6**(런 시작
  몬스터 계획 + 라운드 스케일링 — `RunState.monster_plan` 신설, 20종
  풀에서 중복 없이 뽑기, `legacy_cycle_monster()` 순환 완전 제거, 보류해둔
  슬라임/고블린 재배정도 함께 처리하는 게 안전)부터 순서대로. 아래는 원문
  전문(사용 규칙상 요약하지 않고 그대로 보존 — G-1~G-9 전부 끝나면
  "처리됨"으로 옮기면서 정리).

  사용자 지시 원문: "몬스터가 각각 달라야지 않겠나. 몬스터가 좀 더
  다양해야 할 듯. 그 중에서도 계열은 어느 정도 맞춰서, 고블린 계열은 좀 비슷한 스타일의
  스킬(전투)을 갖도록. 같은 계열인지는 알아야 하니, 상대할 때 이름 쪽에 아이콘으로
  통일성을 갖추자. 예: [인간형 아이콘] 고블린, [인간형 아이콘] 아머 고블린 = 인간형은
  방어 관련 무언가를 함. [부정형 아이콘] 슬라임, [부정형 아이콘] 유령 = 이들은 주사위에
  무언가를 함. 계열을 만들고 거기에서 파생되는 몬스터를 여러 종 만들자. 목표로는
  스테이지마다 모두 다른 몬스터들이 등장해야 함. 다음 회차에서는 또 다른 몬스터들도
  있어야 하니 넉넉한 풀이 필요함. 보스도 보스 전용으로 별도 무언가가 필요할 듯. 각
  라운드마다 보스 2종, 보스 등장은 랜덤. 노멀 풀과 정예 풀에는 각각 몬스터들이 여러
  종류 필요함."
  (현재 상태: 몬스터는 5종뿐이고 `combat_test.gd`의 `MONSTER_PROFILES`를
  `rooms_cleared % 5`로 순서대로 돌려 쓴다 — 라운드 2·3도 같은 5종이 같은 순서/같은
  스탯으로 나오고 보스는 5번째 방 다크 나이트에 스탯만 얹은 것. 정예 전투는 없음.)
  이미 사람이 설계 결정까지 해둔 것이다 — "사람 설계 결정 필요"로 보류하지 말고 **G-1 →
  G-9 순서로 한 이터레이션에 한 조각씩** 진행. 진행 상황은 STATUS.md에 "G-n 완료"로 남기고
  전부 끝나면 "처리됨"으로 옮길 것. **실행 순서: [대형 기획 5]의 F-2, F-3을 먼저 끝낸 뒤
  G-1~G-9, 마지막에 F-4(밸런스 시뮬)** — F-4 시뮬은 최종 몬스터 풀/라운드 스케일링/정예/
  보스까지 포함해서 측정해야 의미가 있으므로 G가 끝난 뒤에 돌린다(F-4a~c의 "기본 몬스터
  5종 × 방 0~4"는 G 완료 후 "계획된 몬스터 + 정예 + 보스, 라운드 1~3"으로 범위를 넓힐 것).

  **원칙(전 단계 공통)**: 몬스터 수십 종을 각각 코드로 짜지 않는다 — **데이터 표 +
  재사용 가능한 "몬스터 스킬 프리미티브"** 로 만든다. 일반 몬스터 = 프리미티브 1개,
  정예 = 2개, 보스 = 3개 + 2페이즈. 몬스터 스킬 로직은 `combat_test.gd`에 흩어 넣지 말고
  **순수 함수**(입력 값 배열 → 출력 값 배열/상태 변화)로 `code/systems/monster_skills.gd`에
  모아 테스트가 같은 코드를 쓰게 한다(F-3의 "효과를 검증" 원칙 — 모든 새 스킬은 "스킬
  있음/없음의 계산 결과가 달라지는가" 테스트를 같이 추가).

  **G-1. 계열 + 몬스터 카탈로그 + 계열 아이콘 (동작 변경 없음)**
  - 신규 `code/systems/monster_catalog.gd`(`MonsterCatalog`): `FAMILIES`(id/이름/설명)와
    `MONSTERS`(id, name, family, tier("normal"|"elite"|"boss"), color, skills(스킬 id+
    파라미터 목록), hp_mult, personality 한 줄). 지금 `MONSTER_PROFILES` 5종을 여기로
    옮기되 **이 단계에서는 전투 동작을 바꾸지 않는다**(기존 gimmick 그대로 유지). 계열 배정:
    슬라임=부정형 / 고블린=인간형 / 해골 전사=언데드형 / 오크=야수형 / 다크 나이트=인간형.
  - 계열 4종: **인간형**(방어/장비 계열), **부정형**(플레이어 주사위를 건드림), **야수형**
    (공격/폭딜 계열), **언데드형**(흡수/부활/지속 계열). 5번째 계열은 만들지 않는다(필요해지면
    나중에).
  - 신규 `code/scenes/family_icon.gd`(`FamilyIcon`, `skill_icon.gd`/`reward_icon.gd`와 같은
    절차적 `_draw()` 패턴): 인간형=방패, 부정형=물방울, 야수형=발톱/송곳니, 언데드형=해골.
    보스는 아이콘 위에 작은 왕관 오버레이(보스 단계에서). 전투 화면의 몬스터 이름 라벨
    **앞**에 계열 아이콘 + 이름("[아이콘] 고블린") 표시. `dice_test.gd`에 "카탈로그의 모든
    family 값이 FamilyIcon.CATEGORIES에 존재" 검증(스킬 아이콘 검증과 같은 패턴).

  **G-2. 몬스터 스킬 프레임워크 + 기존 4종 이식 (동작 보존)**
  - `monster_skills.gd`에 훅 4개: `on_combat_start(state)`(전투당 1회 상태 초기화),
    `modify_monster_roll(values, state, ctx)`(몬스터 자신의 굴림 보정),
    `modify_player_roll(values, state, ctx)`(플레이어 굴림 보정 — 부정형 계열), 
    `on_damage(state, ctx)`(피해 확정 후: 흡수/반사/부활 등). 기존 `anger_stack`/`fixed_value`/
    `min_max_only`/`steady_guard`를 이 구조로 옮긴다(몬스터 쪽 `dice_bag.gd` 헬퍼는 그대로
    호출). **이식 전후 같은 입력이면 같은 결과**임을 효과 테스트로 보장.

  **G-3. 인간형 + 부정형 프리미티브**(수치는 전부 잠정값 — F-4 시뮬로 조정)
  - 인간형(방어): `armor(n)` 몬스터 방어 합계 +n / `guard_up` 몬스터 HP가 절반 이하이면
    몬스터 방어 다이스 결과 +1 / `counter(n)` 플레이어 공격이 몬스터 방어에 완전히 막혀
    데미지 0이면 플레이어가 n 반사 피해 / `steady_guard`(기존).
  - 부정형(플레이어 주사위): `sticky` 플레이어 공격 다이스 중 **가장 높은 1개 -1**(최소
    1) / `seal` 플레이어 공격 다이스 중 **가장 낮은 1개를 0으로** / `dull` 플레이어
    다이스 중 **최댓값 면이 나온 다이스는 전부 최댓값-1로**(폭발/수호 스택 캐릭터의 스택
    조건을 약화 — 의도된 카운터) / `numb` 플레이어 **방어** 다이스 중 가장 높은 1개 -1.
    (`modify_player_roll`은 "공격턴/방어턴" 구분 ctx를 받아 해당하는 턴에만 적용.)

  **G-4. 야수형 + 언데드형 프리미티브**
  - 야수형(공격): `anger_stack`/`min_max_only`(기존) / `pounce(n)` 전투 첫 몬스터 공격 +n /
    `bloodlust` 몬스터 HP 절반 이하부터 몬스터 공격 다이스 결과 +1.
  - 언데드형(지속): `fixed_value`(기존) / `drain` 몬스터가 입힌 피해의 절반(내림)만큼 HP
    회복(최대 HP 초과 불가) / `revive` **전투당 1회**, HP 0이 되면 최대 HP의 30%로 부활
    (부활 시 로그/연출 한 줄) / `chill` 플레이어 방어 다이스 중 가장 높은 1개 -1(부정형
    numb과 겹치므로 chill은 "공격 다이스 중 가장 높은 1개 -1"로 구분해도 됨 — 구현자가
    둘이 같은 효과가 되지 않게만 정할 것).

  **G-5. 일반 몬스터 20종 데이터 (계열당 5종)** — 이름 | 스킬 | 비고(수치는 잠정값)
  - 인간형: 고블린(armor 1) / 아머 고블린(armor 2) / 방패 고블린(guard_up) / 산적(counter 1)
    / 경비병(steady_guard). *고블린 일가는 전부 방어 스킬 — "같은 계열은 비슷한 스타일"*
  - 부정형: 슬라임(sticky) / 독 슬라임(sticky, 몬스터 공격 +1) / 유령(seal) / 그림자(dull) /
    안개(numb)
  - 야수형: 늑대(pounce 3) / 광견(anger_stack) / 오크(min_max_only) / 멧돼지(bloodlust) /
    독거미(pounce 2, 방어 낮음)
  - 언데드형: 해골 전사(fixed_value) / 구울(drain) / 좀비(HP ×1.4, chill) / 해골 궁수(공격
    다이스 +1, 방어 낮음) / 망령 병사(drain, 공격 낮음)
  - 몬스터별 `color`는 서로 구분되게 새로 배정, `personality` 한 줄씩. 초상화 placeholder
    (`monster_portrait_placeholder.gd`)에 `family` 매개변수를 추가해 계열별 실루엣 장식
    (인간형=투구/귀, 부정형=뿔 없이 물방울 하단, 야수형=귀+송곳니, 언데드=눈구멍) 최소 구분.
    **이 단계에서는 아직 풀 뽑기 로직 없이** 카탈로그만 채우고, 전투 화면 QA 캡처용 훅으로
    몬스터 id를 직접 지정해 몇 종을 실제로 띄워 보고 스킬이 효과 있는지 확인.

  **G-6. 런 시작 몬스터 계획 + 라운드 스케일링**
  - `RunState`에 `monster_plan` 신설: `reset_run()`에서 라운드(3) × 방(0~3, 전투 4칸)의
    일반 몬스터를 **일반 풀(20종)에서 한 판 안에서 중복 없이** 미리 뽑아 저장(12종 사용).
    가능하면 같은 계열 **연속 2번 금지**. 난수는 런 시작 시 시드를 `RunState.run_seed`로
    저장해 재현 가능하게(QA/시뮬용). `combat_test.gd`는 `rooms_cleared`/`round_index`로
    계획을 조회해 해당 몬스터를 만든다(`MONSTER_PROFILES % 5` 순환 제거).
  - **난이도 곡선**: `effective_difficulty = rooms_cleared + (round_index - 1) * 3`을 지금의
    `room_index` 대신 기존 스케일링 공식(공격/방어 다이스 개수, HP, 몬스터 다이스 면 수
    D4→D6→D8)에 넣는다. 개수는 MAX_DICE(6) 상한, 면 수는 D8 상한(필요 시 D10은 F-4 이후).
    몬스터 `hp_mult` 반영. 전부 잠정값 — F-4가 측정.
  - 기존 `GAME_QA_ROOM_OVERRIDE` QA 훅은 계획을 우회해 "그 난이도 인덱스의 임의 몬스터"를
    만들도록 호환 유지(기존 스크린샷/테스트 안 깨지게).

  **G-7. 정예 전투 방 + 정예 풀 8종**
  - 던전 맵에 새 방 종류 "정예 전투": 방 1~3에서 확률(잠정 35%)로 일반 전투 **옆에 추가
    선택지**로 노출(상점/이벤트 노출 로직과 같은 결정적 방식). 전용 아이콘(해골+불꽃 느낌,
    reward_icon/범례에 항목 추가 — 던전 맵 범례 문구도 갱신), 버튼에 빨간 테두리.
  - 정예 몬스터는 `monster_plan`에 방별로 같이 미리 뽑아 둠(정예 풀에서 중복 없이). 정예 =
    스킬 2개 + hp_mult 1.5 + 공격 다이스 +1. **보상은 일반 전투보다 커야 함**: 승리 보상
    카드 후보를 A급 이상 중심으로(기존 등급 시스템 재사용) + 골드 ×2. 전투 화면에 "정예"
    배지.
  - 정예 풀 8종: 인간형 — 다크 나이트(steady_guard + armor 2) / 고블린 족장(armor 2 +
    counter 1). 부정형 — 젤라틴 큐브(sticky + dull) / 망령(seal + numb). 야수형 — 오크 투사
    (min_max_only + bloodlust) / 암흑 늑대(pounce 3 + anger_stack). 언데드형 — 해골 기사
    (fixed_value + drain) / 리치 견습생(revive + chill).

  **G-8. 보스 6종 (라운드당 2종, 등장은 라운드 시작 시 랜덤)**
  - `monster_plan`이 라운드마다 보스 후보 2종 중 하나를 `run_seed`로 결정(런 안에서 고정).
