> 로컬에서 직접 열어 확인). 이 문서는 **사용자가 보고 확정하기 위한 비교 자료**이지,

## 공통 사항

- 모든 "후" 시안은 `UIKit`/`CharacterTheme`/`FamilyIcon`/`RewardIcon`/`ItemCardStyle` 등
  **기존 코드를 그대로 재사용**했다 — 새 그리기 로직을 만들지 않고, 기존 함수의
  매개변수(`base_dir`, `size_flags` 등)만 다르게 써서 기준 문서가 요구하는 모습을
  만들었다. 그래서 "후" 모습은 "이런 그림을 그려보면 어떨까"가 아니라 **지금 코드로
  실제로 켤 수 있는 상태**에 가깝다.
- 장식을 낮추는 항목(S-6)은 새 아트 없이 `MockupCommon.FLAT_SKIN_DIR`(존재하지 않는
  경로)를 넘겨 이미지 스킨 로드를 실패시키고 기존 절차적 `StyleBoxFlat` 폴백을
  끌어쓰는 방식으로 근사했다 — "장식이 없으면 이렇게 읽기 쉬워진다"는 근사치이지,
  최종 아트 방향은 아니다(9절 아트 요청 참고).
- 각 화면의 640x360 축소본(`<화면>_after_640.png`)과 흐림 처리본
  (`<화면>_after_blur.png`, 16배 축소 후 재확대로 근사한 흐림)을 함께 만들었다 —
  "작게 봤을 때/눈을 가늘게 떴을 때도 1순위가 먼저 읽히는가"를 직접 확인하는 용도
  (VISUAL_STANDARD.md 3절 검증 방법).
- 화면마다 `<화면>_keys.png`에 번호+화살표로 키 이동 경로(VISUAL_STANDARD.md 8절
  표)를 겹쳐 그렸다.

**결정이 필요한 질문**:
1. 정보 패널을 고정 좌표(x=980, 폭 260)로 못 박는 대신, 창 크기에 비례하는 레이아웃이
   필요한가 — project.godot의 `stretch`(canvas_items+keep, 2026-10-27 추가)가 이미
   비율 유지 확대/축소를 하므로 "고정 좌표 + 전체 화면 비율 유지"면 충분한지, 아니면
   별도 반응형 앵커가 필요한지.
2. `RewardIcon`/`FamilyIcon`을 쓰는 다른 화면(전투 HUD, 상점, 보상, 업적)도 전부
   같은 `SIZE_SHRINK_CENTER` 처리가 필요하다 — 본 구현 때 `UIKit`에 "아이콘 슬롯"
   공용 헬퍼로 묶는 것과, 호출부마다 개별로 고치는 것 중 어느 쪽이 나은가(전자는
   누락 방지, 후자는 변경 범위가 작음).

## 9. 공통 결정 필요 사항 (여러 화면에 걸침)

1. **S-6 "더 얇고 차분한 UI 키트"의 실제 방향**: 이 시안은 전부 "장식을 끈 플랫
   스타일"로 근사했다. 실제로는 (a) 지금 스킨을 유지하되 글자 주변만 비우는 수정,
   (b) 아예 새 차분한 스킨 세트 발주, (c) 이 시안처럼 테두리 위주 플랫 스타일을
   정식 채택 — 셋 중 어느 방향인지 확정이 필요하다.
2. **상태 메시지 바(S-3)의 노출 트리거**: 캐릭터 선택/이벤트 두 시안 모두 "조건
   미충족 동안 항상 보임"으로 구현했다 — 이게 모든 화면에 맞는 기본값인지.

## 10. 알려진 한계 (이 시안 자체의 한계)

- 시안은 고정 예시 데이터만 쓴다 — 실제 게임 상태(골드 0, 주머니 꽉 참, 몬스터
  다양한 티어 등) 극단값에서도 레이아웃이 깨지지 않는지는 본 구현 때 실제 화면에서
  재검증해야 한다.

  구현 때는 이 디렉터리를 그대로 승격하지 않고 `code/scenes/`의 실제 화면 코드를
  고친다(시안은 참고용으로 남겨두거나 정리, 결정은 본 구현 착수 시).
