## 0. 반려 사유 (1단계)

감독이 직접 지적한 내용 그대로:

- **캐릭터 선택 "후"**: 8명 중 4명만 있고, 능력치·고유 능력·스킬 도감 버튼·던전 입장
  버튼이 사라짐. 전신 원화가 화면 뒤에 거대하게 잘려 깔림. 시작 스킬 패널 아래가
  텅 빔.
- **전투 "후"**: 배경·캐릭터와 몬스터 초상·다이스 스테이지·공격/방어 다이스 줄·몬스터
  정보가 전부 빠지고 전투 기록만 화면을 채움.
- **던전 맵 "후"**: 방 카드가 빈 막대로만 남음.
- **총평**: "전"보다 못하다 — 개편 시안이 아니라 내용 대부분을 지운 와이어프레임.

원인: 1단계 시안은 각 화면을 **처음부터 새로 그려서** 고정 예시 데이터(캐릭터 1명,
카드 몇 장)만 흉내 냈다. VISUAL_STANDARD.md가 요구하는 "장식을 낮추는" 작업에
집중하느라 "장식이 아닌 실제 콘텐츠"까지 함께 들어냈다.

## 1. 재작업 방식

각 시안을 **`code/scenes/`의 실제 `.tscn`을 그대로 `instantiate()`해 자식으로 붙이고,
그 실제 노드 트리 위에서 VISUAL_STANDARD.md가 요구하는 자리만 코드로 패치**하는
방식으로 전부 다시 만들었다(`MockupCommon.find_nodes()`/`find_label_with_text()`/
`restyle_button()`/`fix_icon_aspect()` 등 신규 공용 헬퍼, `code/mockups/
mockup_common.gd`). 실제 씬 파일은 한 글자도 바꾸지 않았다 — 대신:

- 캐릭터 8명, 능력치, 고유 능력, 배경 원화, 상단 버튼, 던전 입장 버튼 등은 실제
  `character_select.gd`의 `_ready()`가 그대로 그린다(= "전"과 완전히 같은 콘텐츠).
- "승리 보상"처럼 **별도 씬이 없는 화면**(combat_test.gd의 한 상태)은 실제
  `combat_test.tscn`을 인스턴스화한 뒤 기존 QA 전용 훅(`_debug_show_reward_after_
  last_exchange()`, 새로 만든 것 아님 — 기존 코드에 이미 있던 0-arity 디버그 메서드)을
  호출해 실제 보상 로직(`DiceItemPool`/`ItemCardStyle`)이 만든 진짜 카드를 그대로
  보여준다.
- "정비"/"몬스터 도감"처럼 **부모 화면의 자식 패널**인 경우(CustomizePanel,
  MonsterCodexPanel) 부모 씬(dungeon_map.tscn/character_select.tscn)을 인스턴스화한
  뒤 그 패널의 실제 `open()`을 호출한다.
- 패치는 전부 "숨기기/치수 조정/스타일 재적용"뿐이고, 새 그리기 로직을 추가한 곳은
  상태 메시지 바(`MockupCommon.make_status_bar()`, 1단계부터 있던 헬퍼)뿐이다.

## 2. 공통 결정 필요 사항 (화면별 질문보다 먼저 읽어주세요)

1. **S-6 "더 얇고 차분한 UI 키트"의 실제 방향**: 버튼/필터 칩 장식을 A안(기존 스킨
   유지 + 글자 외곽선/크기 보강)과 B안(장식 없는 얇은 테두리 플랫) 두 가지로
   캐릭터 선택·몬스터 도감 화면에서 비교할 수 있게 만들었다
   (`qa_out/mockups/character_select_after_A.png`/`_after_B.png`,
   `monster_codex_after_A.png`/`_after_B.png`). **측정 결과**(`code/qa/
   pixel_contrast.gd`, 4.5:1 기준):

   | 요소 | A안(스킨 유지+글자 보강) | B안(플랫) | 원래(1단계 실측) |
   | --- | --- | --- | --- |
   | 상단 "몬스터 도감" 버튼 글자 | **17.62 : 1 PASS** | **14.84 : 1 PASS** | (버튼 자체는 1단계 때 측정 안 함, 이번에 신규 측정) |
   | 몬스터 도감 필터 "전체" 글자 | **17.99 : 1 PASS** | **14.87 : 1 PASS** | 1.86 : 1 **FAIL**(VISUAL_STANDARD.md 2-2절) |

   **두 안 모두 기준을 여유 있게 통과한다** — A안이 수치는 더 높지만(스킨의 어두운
   부분과 겹친 샘플이라 유리), B안도 14.8:1로 이미 충분하다. 다른 6개 화면은
   **B안(플랫)으로 통일**했다(근거: (1) 수치 차이가 실사용에 체감될 정도가 아니고,
   (2) B안이 장식 채도/밝기 편차 문제의 "원인 자체를 없애는" 더 단순한 해법이라
   스킨 텍스처가 바뀔 때마다 재점검할 필요가 없음). **질문**: A/B 중 하나로 전체
   확정할지, 화면마다 다르게 가도 될지(예: 캐릭터 선택처럼 장식이 중요한 화면은
   A, 도감/필터처럼 정보 밀도가 높은 화면은 B)?
2. **상태 메시지 바(S-3)의 위치 예외**: 규격(VISUAL_STANDARD.md 7-2)은 "하단 고정,
   하단에 다른 고정 UI가 있으면 상단 고정"이다. 캐릭터 선택은 하단에 "던전 입장"이
   있어 상단(기존 단계 표시가 있던 자리)에 뒀고, 상점/정비/던전 맵처럼 상단에도
   하단에도 다른 버튼이 있는 화면은 이번 시안에 상태 바를 추가하지 않았다(이벤트는
   하단 버튼 위 빈 공간에 들어감). **질문**: 상점/상점류 화면의 상태 바는 생략해도
   되는가(애초에 "선택해야 할 것"이 명확한 화면이라 필요성이 낮다는 판단), 아니면
   자리를 새로 만들어야 하는가?
3. **`FocusNav` 영역(region) 모델(S-8)**: 이번 시안도 정적 패치라 실제 키보드 이동
   로직은 구현하지 않았다(`_keys.png`는 여전히 "이렇게 이동해야 한다"는 설계도).
   VISUAL_STANDARD.md 8절 표 그대로 진행해도 되는지 확인 필요(1단계와 동일 — 변경
   없음).

버튼을 늘리는 패치를 추가해 해결했다(`_test_cs2_crop.png`).

**자평**: 전보다 뚜렷이 나아졌다 — 8명 전원, 실제 능력치/원화, 모든 버튼이 그대로

단계 표시 제거+상태 바)가 실제로 보인다.

**결정이 필요한 질문**:
1. 잠긴 카드의 해금 조건을 지금처럼 카드 안 전체 문장으로 둘지, 짧은 요약만 넣고
