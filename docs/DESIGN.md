# 게임 디자인 문서 (DESIGN.md)

> 이 문서는 "무엇을 만드는가"를 정의한다. 모든 이터레이션은 이 문서를 먼저 읽고 시작한다.
> 최초 작성: 2026-08-31 (사용자 인터뷰 기반)
> 갱신: 2026-08-31 (전투 시스템 문답 반영)

## 장르

로그라이크 던전 크롤러 + **다이스 빌딩**

## 참고작 / 톤

슬레이 더 스파이어(Slay the Spire), 백팩 히어로(Backpack Hero)와 유사한 톤.
카드 대신 **주사위**로 빌드를 짠다는 점이 핵심 차별점.

## 핵심 루프 (던전 진행)

```
방 선택 → 이벤트 발생 (전투 / 상점 / 선택지 이벤트 등) → 보상 획득 → 다음 방 이동
```

## 코어플레이 재미 축

- **다이스 주머니 빌드업**: 전투 전후 얻는 아이템으로 주사위를 개조한다.
  (예: 모든 면을 6으로 만들기, 6면체를 8면체로 교체하기)
- **손맛/피드백**: 여러 개의 다이스가 굴러가며 나는 소리와 움직임 자체가 재미 요소.
  구르는 다이스의 개수·비주얼·사운드는 QA 스크린샷/플레이 검증에서 중요하게 다룰 것.

## 전투 시스템

### 다이스 주머니 (덱 역할)

- **공격 주머니**와 **방어 주머니**, 두 개의 독립된 다이스 풀을 가진다.
  (덱빌딩 게임의 "덱 두 개"라고 생각하면 됨 — 서로 다른 아이템/개조로 따로 빌드된다)
- 각 주머니는 매 턴 **전체를 굴리고 소모한 뒤 다시 채운다** (재보충형, 슬더스 스타일 턴제).

### 값 반영 방식

- **족보(포커식 조합)·슬롯 배치는 사용하지 않음.**
- **다이스 눈의 합계를 그대로 사용**한다 (높은 값이 곧 좋은 값).
- 공격/방어는 양쪽(플레이어·몬스터) 모두 각자의 공격 주머니 / 방어 주머니를 가지는
  **대칭 구조**다:
  - 공격 측: 공격 주머니 굴림 → 공격 합계
  - 방어 측: 방어 주머니 굴림 → 방어 합계
  - **최종 데미지 = max(0, 공격 합계 − 방어 합계)**
  - (몬스터도 방어 주머니를 가지므로, 플레이어 공격도 몬스터의 방어 합계만큼 감소한다)

### 턴 순서

```
1. 내 공격턴  → 내 공격 주머니 굴림 vs 몬스터 방어 주머니 굴림
              → 데미지 = max(0, 내 공격 합계 - 몬스터 방어 합계) → 몬스터 HP 감소
2. 몬스터 공격턴 (= 내 방어턴) → 몬스터 공격 주머니 굴림 vs 내 방어 주머니 굴림
              → 데미지 = max(0, 몬스터 공격 합계 - 내 방어 합계) → 내 HP 감소
3. 1~2 반복 (적 또는 플레이어 HP가 0이 될 때까지)
```

- 몬스터도 플레이어와 동일하게 공격/방어 주머니를 굴려서 값을 낸다 (완전 무작위 고정
  데미지가 아니라, 다이스를 굴려 매번 값이 달라짐). 다만 몬스터의 주머니 구성 자체는
  고정되어 있고 개조되지 않는다는 점이 플레이어와 다르다 (아래 "확정된 세부 사항" 참고).

### 빌드업 (다이스 개조)

- 전투 전후로 얻는 아이템을 통해 주사위를 개조한다.
- 개조 예시:
  - 특정 면의 값을 올리기 (예: 1을 6으로)
  - 주사위 자체를 교체 (6면체 → 8면체 등, 면 개수 자체를 늘려 기댓값 상승)
  - 공격 주머니 / 방어 주머니에 새 주사위 추가
- 개조는 공격 주머니와 방어 주머니에 각각 독립적으로 적용 가능해야 한다
  (플레이어가 "공격에 몰빵" 또는 "방어에 몰빵" 같은 빌드 방향을 선택할 수 있게).

## 확정된 세부 사항 (첫 프로토타입 기준)

### 초기 다이스 구성 (플레이어)

- **기본값(견습 모험가, 기믹 없음)**: 공격 주머니 4면체(D4) 3개 / 방어 주머니 4면체(D4)
  3개.
- **2026-09-15부터 캐릭터별로 시작 다이스 개수 배분이 다름**(INBOX.md 2026-09-14
  "캐릭터별 현재 개성 및 스타일에 맞추어 시작 주사위를 다르게 한다" 반영, 면 개수는
  5종 전부 D4로 동일하고 공격/방어 다이스 "개수" 배분만 다름) — 광전사(공격4/방어2,
  극단형 공격 몰빵) / 수호자(공격2/방어4, 안정형 방어 몰빵) / 폭발병(공격4/방어3,
  공격 다이스 최댓값 스택을 더 자주 쌓게) / 주술사(id: shieldbearer, 공격3/방어4,
  방어 다이스 최댓값 스택을 더 자주 쌓게, 2026-09-24 리스킨 — 구명 "방패병"→"침묵의
  무녀"→"주술사", id/기믹/수치는 그대로). 정의는 `code/systems/character_profiles.gd`
  (`CharacterProfiles.PROFILES`의 `attack_count`/`defense_count`)에 있고,
  `RunState.reset_run()`이 이 값으로 주머니를 생성한다. 배분 수치는 감으로 잡은
  잠정값 — 실제 밸런스는 사람 플레이 피드백 필요.

### 시작 몬스터 (첫 적, 테스트용)

- **공격 주머니**: 4면체(D4) 2개 (2D4)
- **방어 주머니**: 4면체(D4) 1개 (1D4)
- (몬스터도 플레이어와 동일한 공격/방어 주머니 구조를 따른다. 다만 구성이 고정되어 있고
  개조/성장이 없다는 점이 플레이어와의 차이. 몬스터별로 이 구성이 달라질 수 있음 — 지금은
  테스트용 몬스터 하나만 확정)

### 체력(HP) / 승패 조건

- 승리/패배 조건: **HP가 0이 되면 패배/처치**
- 플레이어 초기 HP: **20**
- 테스트용 몬스터 HP: **10**

### 2D/3D 혼합 구조

- **다이스만 3D**로 물리 시뮬레이션 (구르고, 부딪히고, 재질별 소리가 남).
- **캐릭터, 배경, UI 등 나머지는 2D**로 진행.
- 구현 확정: 2D 씬 안에 3D 다이스용 SubViewportContainer + SubViewport
  (transparent_bg=true)를 두어 3D 물리 다이스를 2D 배경/UI 위에 합성한다
  (`combat_test.tscn` 등에서 실제로 검증 완료, 다른 방식은 검토 불필요).

### 다이스 연출: 물리 시뮬레이션 + 재질별 사운드

- 다이스는 **물리 시뮬레이션**으로 굴러간다 (연출용 애니메이션이 아니라 실제 물리 바디로
  떨어지고, 구르고, 서로 부딪힘).
- 재질(Material) 개념이 있고, 재질에 따라 충돌/구르는 소리와 **시각 색**이 달라진다.
  - 기본(시작) 재질: **플라스틱**
  - 유리/나무/철제 재질을 추가함(물리 bounce/friction 값, 합성 충돌음, 시각 색까지
    재질별로 구현됨 — 플라스틱=연회백/광택, 나무=갈색/무광, 유리=옅은 청록 반투명,
    철제=은회색/금속. 시각 색은 2026-09-03에 추가 — 그 전에는 재질이 물리/소리만
    다르고 넷 다 같은 무채색 회색이라 다면체를 얻어도 눈으로 재질 차이를 못 느끼는
    문제가 있었음). 다만 플레이어가 재질을 직접 고르거나 획득하는 시스템은 아직
    없어서, 지금은 다이스 면 개수(sides)에 따라 코드가 잠정 배정한다(D4/D6=플라스틱,
    D8=나무, D10=유리, D12/D20=철제 — "개조로 다이스가 커질수록 고급 재질처럼
    보인다"는 감으로 잡은 잠정 매핑). 실제로 그럴듯한지, 재질을 플레이어가 직접
    고르는 것으로 바꿀지는 사람 피드백 필요.
- 구현 시 유의점 (다음 이터레이션 참고):
  - 바닥 충돌, 다이스-다이스 충돌, 구르는 동안의 마찰 소리를 재질별로 트리거해야 함
  - Godot에서는 RigidBody3D(또는 2D 프로젝트면 RigidBody2D + 의사-3D 연출) +
    PhysicsMaterial + 충돌 시 AudioStreamPlayer로 구현하는 방향을 우선 검토
  - 시각 QA(`GAME_QA_FRAME`)는 다이스가 굴러서 완전히 멈춘 시점 이후로 프레임을 잡아야
    스크린샷이 의미 있음 — 물리 시뮬레이션 특성상 멈추는 시점이 매번 조금씩 다를 수 있음.
    **결정: "정지 감지 후 캡처" 방식으로 확정, 구현 완료** (2026-09-03). 씬이
    `_qa_is_settled() -> bool`을 구현하면(예: `combat_test.gd`), QA 실행 시
    `GAME_QA_SETTLE=1`을 켰을 때 `GAME_QA_FRAME`에 도달해도 그 값이 true가 될 때까지
    캡처를 미룬다(`code/qa/visual_qa.gd`). 이 훅이 없는 씬은 기존과 동일하게
    `GAME_QA_FRAME`에서 바로 캡처(하위 호환). `scripts/qa_shot.sh <scene> <frame>
    [out] [qa_call] 1`의 5번째 인자로 켤 수 있음.

**2026-10-13 [대형 기획 11] K-1로 숫자 단축키를 완전히 대체** — 마우스/터치 클릭은

| 키 | 동작 |
| --- | --- |
| 방향키(↑↓←→) | 포커스(강조 테두리)를 화면에 보이는 버튼들 사이에서 이동 |

화면마다 버튼을 "방향키 한 줄 체인"으로 명시적으로 연결해(`code/scenes/focus_nav.gd`의
`FocusNav`) 방향키 이동이 시각적 순서와 일치하게 한다. 오버레이 패널(커스터마이징/업적)이
열려 있는 동안은 포커스가 패널 밖(뒤에 가려진 화면)으로 못 나가도록 체인을 닫힌 루프로
묶는다(`wrap`+`trap`). 과거(2026-09-14~2026-10-08)에 썼던 "버튼에 [1]~[9] 숫자
접두어를 붙이고 숫자 키로 직접 누르는" `KeyboardShortcuts` 방식은 이번에 완전히
삭제됐다 — 화면에 숫자 힌트가 전혀 남지 않는다.

적용 화면: character_select(캐릭터 카드/시작 스킬 슬롯/던전 시작·업적·테스트 전투
버튼), dungeon_map(방 선택), combat_test(보상 선택/다음/덱·커스터마이징 토글 —

story_event, customize_panel/achievement_panel(오버레이, 포커스 트랩 + Esc 닫기),
test_battle_setup("뒤로"/"전투 시작"만 — 나머지 설정 컨트롤은 Godot 기본 포커스
동작에 맡김). **deck_panel은 2026-10-17 [대형 기획 15] Q-4b(11)부터 "보유 스킬" 행이
클릭/Space로 SkillDetailPopup(이름+효과 설명, 공용 컴포넌트)을 띄우는 첫 포커스
대상이 생겼다** — 목록 안에서는 방향키(위/아래)로만 이동(wrap/trap 없음, 화면 전체
체인과는 별개 축), 팝업 자체는 다른 오버레이와 동일하게 포커스 트랩 + Esc/배경

  그 외 화면은 화면 진입 시 그 런의 캐릭터 색으로 즉시 시작한다(애니메이션 없음 —
  이미 정해진 캐릭터라 전환할 "이전 색"이 없음).
- **화면 제목(상단 HUD)**: `CharacterTheme.apply_label(label, character_id)`(신규
  공용 헬퍼, accent 색) — 위 6개 화면의 "Title" 라벨에 전부 적용.
- **주요 패널 테두리**: `CharacterTheme.apply(panel, character_id)`(K-3부터 있던
  헬퍼) — 캐릭터 선택 상세 패널 5섹션(K-3)·`DeckPanel`(K-3)에 이어, L-3로
  `CustomizePanel`/`AchievementPanel`/`SkillCodexPanel`의 틀(기존엔 테두리 없는
  단순 검정 `ColorRect`였던 것을 `Panel`+`StyleBoxFlat`로 바꿈)에도 적용됐다.
- **포커스 강조색**: K-1부터 있던 `FocusNav.focus_style()`의 accent 매개변수 — 위
  모든 화면/오버레이 패널에서 그대로 유지.
- **적용되지 않는 곳**: 전투 중 다이스 3D 지오테메트리·재질 색(DESIGN.md "다이스

  캐릭터가 없으므로 퍼스널 컬러 대상이 아님).
- 대비(WCAG AA 4.5:1 이상)는 `ui_palette()`가 `panel_bg`를 항상 어둡게,
  `text`를 그 배경 대비로 보정해 자동 보장 — 8명 전부 12~13대1로 여유 있게
  통과(계산은 `code/scenes/dice_test.gd`의 K-3/L-3 검증 참고).

## UI

[대형 기획 13] M-1~M-5(2026-10-14~15, M-4가 2026-10-15에 마지막으로 완료되며 전체
마무리)로 캐릭터 선택 화면(K-2/K-3)이 먼저 확립한 "구역 패널 + 테두리 + 퍼스널 컬러 +
버튼 위계" 시각 언어가 던전 맵 → 전투 → 이벤트/상점/스토리 이벤트 순으로 전 화면에
퍼졌다. `code/systems/ui_kit.gd`(`UIKit`)가 이 패턴들을 공용 팩토리 함수로 제공해
화면마다 같은 스타일 코드를 복붙하지 않게 한다 — M-5(a)/(b)로 ProjectD Art가 납품한
`resources/ui/` 이미지 스킨(패널/버튼/HP 바/배지/장식/아이콘)도 전부 이 팩토리들
내부에서 "있으면 쓰고, 없으면 절차적 StyleBoxFlat/ColorRect로 폴백"하므로 호출부는
스킨 유무를 몰라도 된다.

`character_select`는 `CharacterCardPanel`/상세 패널 5섹션 전용 구조라 `UIKit` 팩토리
대신 `CharacterTheme.apply()`를 직접 쓴다(K-2/K-3가 먼저 확립한 패턴 — `UIKit`은 그

컬러 팔레트·배경·라벨 틴트(`CharacterTheme`, 위 "퍼스널 컬러 적용 범위" 절 참고)와

퍼스널 컬러로 틴트하지 않고 독립적으로 유지한다(M-5(a) 때 사람 결정 보류 사항).

파일이 전혀 없는 상태(아트 미입고)에서도 위 전부가 기존 절차적 스타일 그대로 동작 —
`resources/ui/`(M-5a/b) 자산은 "있으면 쓰고 없어도 안 깨지는" 선택적 스킨이다.

정상 플레이(QA 환경변수 없이)에서는 `RunState.monster_plan`/`RunState.elite_plan`
(둘 다 런 시작 시 `MonsterCatalog.build_monster_plan()`/`build_elite_plan()`으로
한 번에 미리 뽑혀 저장 — `RunState.run_seed`로 재현 가능)이 라운드×방마다 어떤
몬스터가 나오는지를 정한다. 일반 전투 자리(라운드당 4칸, 3라운드 x 4 = 12자리)는
**일반 20종 풀에서 런 전체에 걸쳐 중복 없이** 뽑히고(풀 크기 20 ≥ 12라 가능, 가능하면
같은 계열 연속 2번도 피함), 각 라운드 마지막 방(5번째, 보스 자리)은 **그 라운드의
보스 후보 2종 중 `run_seed`로 고정된 하나**다. "정예 전투"는 방 1~3에서 35%
확률(`dungeon_map.gd`의 `ELITE_CHANCE`)로 일반 전투 옆에 추가 선택지로 노출되고
(빨간 테두리 버튼), 정예 몬스터는 라운드마다 정예 8종 풀에서 중복 없이 배정된다.
던전 맵의 "전투"/"정예 전투" 선택지 옆에는 **다음에 만날 몬스터의 계열 아이콘**이
미리 표시된다(G-9, 2026-10-07 — 상점/이벤트와 달리 전투는 스포일링 문제가 없어
노출, `dungeon_map.gd`의 `_monster_profile_for_room()`/`_elite_profile_for_room()`
이 `combat_test.gd`와 같은 `RunState.monster_plan`/`elite_plan`을 읽으므로 미리보기와
실제 결과가 항상 일치한다).

방이 진행될수록 공격/방어 다이스 개수·면 개수·HP가 함께 커진다(난이도 공식은
`room_index + (round_index-1)*3` = `difficulty`, `combat_test.gd`의
`_build_monster_config()`). 다이스 면 개수는 `difficulty`에 따라 D4(0~2)→
D6(3~6)→D8(7+)로 승급한다(`_monster_dice_sides_for_room()`, 임계 D6>=3/D8>=7 —
**[대형 기획 10] J-3(2026-10-12)에서 균형 성장 밸런스 시뮬 기준으로 두 임계를
분리해 조정한 최종값**, 최초값은 D6>=2/D8>=5였다). 보스는 **전용 스킬 2~3개 +
HP 50% 이하에서 1회 발동하는 2페이즈(전용 스킬 1개 추가 또는 기존 스킬 강화) +
초상화 1.25배 확대**를 갖지만, 공격/방어 다이스 개수와 HP의 보스 전용 공통
가산(최초값 공격+2/방어+1/HP×2)은 **[대형 기획 10] J-2(2026-10-08)에서 균형
정책 보스 평균 승률(목표 35~55%)을 맞추느라 전부 제거됐다**(현재 공격+0/방어+0/
HP×1.0 — 난이도 공식·몬스터별 `atk_dice_delta`/`def_dice_delta`/`hp_mult`만
그대로 적용됨, 상세 시도 경위는 `docs/BALANCE_TUNING_LOG.md` 참고). 정예는
**스킬 2개 + hp_mult 1.5 + 공격 다이스 +1**(8종 공통 공식, J-2/J-3에서 건드리지
않은 최초값 그대로)로 일반보다 강하고, 승리 보상도 크다(골드 ×2 +
`EliteRewardPool`로 A급 이상 카드 중심). 이 스케일링 수치(난이도 공식의 가산폭
3, 몬스터별 delta/hp_mult 등)는 여전히 다른 부분은 잠정값이고, 밸런스 시뮬
(`docs/BALANCE_GROWTH_REPORT.md`/`docs/BALANCE_TUNING_LOG.md`)로 목표 밴드
(일반 방0~2 85~100%/방3 75~85%/정예 55~70%/보스 35~55%, 균형 성장 정책·8캐릭터
평균 기준) 안에 들어온 것만 확인된 상태다.

몬스터 스킬("다이스 기믹")은 몬스터 수십 종을 각각 코드로 짜는 대신, **재사용 가능한
"스킬 프리미티브"**(`code/systems/monster_skills.gd`의 `MonsterSkills`, 순수 함수 —
훅 4개: `on_combat_start`/`modify_monster_roll`/`modify_player_roll`/`on_damage`)로
조합한다 — 일반 몬스터 = 프리미티브 1개, 정예 = 2개, 보스 = 3개(+2페이즈로 1개 추가).
수치(n)는 전부 감으로 잡은 잠정값(F-4 밸런스 시뮬로 조정 예정).

#### 스킬 프리미티브 범례 (계열별)

| id | 계열 | 효과 |
|---|---|---|
| `armor(n)` | 인간형 | 몬스터 방어 합계 +n |
| `guard_up` | 인간형 | 몬스터 HP가 최대 HP 절반 이하면 몬스터 방어 다이스 결과 +1 |
| `counter(n)` | 인간형 | 플레이어 공격이 몬스터 방어에 완전히 막혀(데미지 0) 실패하면 플레이어에게 n 반사 피해 |
| `steady_guard` | 인간형 | 몬스터 방어 다이스 결과가 면 개수 절반(올림) 미만이면 그 값으로 보정(하한선만 보장, 면 값 자체는 매번 다름) |
| `sticky` | 부정형 | 플레이어 공격 다이스 중 가장 높은 1개 -1(최소 1) |
| `seal` | 부정형 | 플레이어 공격 다이스 중 가장 낮은 1개를 0으로 |
| `dull` | 부정형 | 플레이어 다이스 중 최댓값 면이 나온 다이스는 전부 최댓값-1로(폭발/수호 스택 캐릭터의 스택 조건을 약화하는 의도된 카운터) |
| `numb` | 부정형 | 플레이어 **방어** 다이스 중 가장 높은 1개 -1 |
| `anger_stack` | 야수형 | 몬스터 공격 다이스가 최댓값을 보일 때마다 분노 스택 적립, 임계치에서 다음 공격 1턴만 1D20 |
| `min_max_only` | 야수형 | 몬스터 공격/방어 다이스가 최소·최댓값만 나옴(중간값 없음) |
| `pounce(n)` | 야수형 | 전투 첫 몬스터 공격턴에만 몬스터 공격 다이스 결과 +n |
| `bloodlust` | 야수형 | 몬스터 HP가 최대 HP 절반 이하부터 몬스터 공격 다이스 결과 +1 |
| `fixed_value` | 언데드형 | 몬스터 공격/방어 다이스가 항상 같은 값만 나옴(면 개수 절반 근처로 반올림, 안 굴림) |
| `drain` | 언데드형 | 몬스터가 입힌 피해의 절반(내림)만큼 몬스터 HP 회복(최대 HP 상한) |
| `revive` | 언데드형 | 전투당 1회, 몬스터 HP가 0 이하가 되면 최대 HP의 30%로 부활 |
| `chill` | 언데드형 | 플레이어 **공격** 다이스 중 가장 높은 1개 -1(sticky와 공식은 같지만 다른 몬스터에 배정돼 계열 구분용) |

#### 일반 몬스터 20종 (계열당 5종, `tier="normal"`)

| 야수형 | 오크 | `min_max_only` | 힘만 믿고 저돌적으로 날뛰는 성격, 전부 아니면 전무 |
| 야수형 | 멧돼지 | `bloodlust` | 피를 흘릴수록 더 거세게 돌진하는 멧돼지 |
| 야수형 | 독거미 | `pounce(2)`, 방어 다이스 -1개 | 방어는 허술해도 첫 기습만큼은 치명적인 거미 |
| 언데드형 | 해골 전사 | `fixed_value` | 감정 없이 명령대로만 움직이는 병사, 늘 같은 힘으로 정확하게 타격 |
| 언데드형 | 구울 | `drain` | 할퀸 상처에서 생기를 빨아들여 되살아나는 구울 |
| 언데드형 | 좀비 | `chill`, HP ×1.4 | 둔하지만 쉽게 쓰러지지 않는, 서늘한 기운을 내뿜는 좀비 |
| 언데드형 | 해골 궁수 | 없음, 공격 다이스 +1개 / 방어 다이스 -1개 | 방어는 포기하고 화살 공세에만 집중하는 해골 |
| 언데드형 | 망령 병사 | `drain`, 공격 다이스 -1개 | 약한 공격으로도 꾸준히 생명력을 갈취하는 병사 |

여부와 완전히 무관하게**(진행도/업적 기록 없음) `MonsterCatalog.MONSTERS`
전체(35종 — 일반 20+레거시 다크 나이트 1+정예 8+보스 6)를 항상 전부 보여준다 — 몬스터
id 하드코딩 없이 카탈로그를 순회해 만들므로 새 몬스터가 추가되면 자동으로 격자에
나타난다. 두 단계 뷰:

- **격자 뷰**: 계열(전체+4종)·티어(전체+3종) 필터 버튼 행 + 카드 격자. 카드마다 계열
  아이콘(`FamilyIcon`, 보스는 왕관·정예는 빨간 테두리)·이름·"원화 ✓/✗ · 표정 n/5"
  리소스 입고 태그를 보여준다.
- **상세 뷰**: 카드를 클릭/Space하면 전신 `full.png`를 크게 보여주고, 그 옆에 표정
  5종(neutral/happy/hurt/sad/angry) 전환 버튼(`CharacterArt.face_path()`로 파일이
  없는 표정은 버튼 자체가 disabled — 미입고 표정은 전환 불가)과 전투 화면에서 실제로
  쓰는 상반신 크롭 미리보기(`CharacterArt.load_full_crop()`, 티어별 크롭 비율 재사용)를
  나란히 두고, 우측에 파일별 입고 현황(full.png + 표정 5장 각각 ✓/✗) 체크리스트를
  보여준다. 이름/id/계열/티어/성격 문구/스킬(+보스 2페이즈) 목록도 함께 표시. **2026-10-20
  현재 입고된 34종 전부 `full.png`만 있고 `face_*` 표정 컷은 아직 하나도 없어**(아트
  스레드 작업 진행 중), 표정 버튼이 전부 비활성화되고 "표정 미입고 → 오른쪽 크롭 참고"

  화면으로 들어간다. 설정 화면의 "뒤로"로 캐릭터 선택 화면에 복귀한다. 정식 빌드에서
  이 기능 자체를 숨기고 싶으면 `RunState.TEST_BATTLE_ENABLED`(단일 상수) 하나만
  `false`로 바꾸면 버튼이 사라진다(코드 삭제 불필요).
- **직전 선택 유지**: 캐릭터/시작 스킬/몬스터/난이도/성장/보유 스킬 선택은 바뀔 때마다
  즉시 `RunState.test_*` 필드에 반영되고, 이 필드들은 `RunState.reset_run()`이 건드리지
  않으므로 전투 후 "설정으로 돌아가기"로 이 화면이 다시 로드돼도 그대로 남아
  반복 테스트가 편하다.

## "이 정도면 됐다" (Definition of Done) — 이터레이션별 판단 기준

시각 QA는 두 층위로 판단한다.

### 1. 자동 판단 (스크린샷 레벨, AI가 매 이터레이션 스스로 확인)

- 지정한 씬(`GAME_START`, 예: `dungeon`)이 **크래시 없이 로드**된다.
- 지정한 프레임(`GAME_QA_FRAME`)에서 **스크린샷이 정상적으로 저장**된다 (파일 존재, 0바이트 아님).
- 이 두 조건을 통과하지 못하면 그 이터레이션은 실패로 간주하고, 다음 이터레이션에서 반드시
  원인을 고쳐야 한다. (`scripts/qa_shot.sh <scene>` 로 검증)

### 2. 사람 판단 (플레이 피드백 레벨, 사용자가 직접 플레이해서 판단)

- 자동 기준을 통과했더라도, 최종 판단은 사용자가 직접 플레이해보고 느끼는 개별 피드백이다.
- UX, 밸런스, 비주얼, 재미(특히 다이스 굴러가는 손맛), 버그 등 무엇이든
  `docs/feedback/INBOX.md` 에 남긴다.
- AI는 매 이터레이션 시작 시 INBOX.md를 **가장 먼저** 읽고 **최우선으로** 반영해야 한다.

## 아직 정해지지 않은 것 (다음 이터레이션들이 채워나갈 부분)

- 상점/선택지 이벤트의 구체적 내용
- 다이스 개조 아이템의 종류와 강도 곡선
- 아트 스타일 (참고작 톤은 정해졌으나 구체적 리소스/팔레트는 미정)
- 던전 길이 (방 개수), 런 전체 구조 — 잠정으로 `RunState.TOTAL_ROOMS = 5`를 코드에
  넣어 "런에 끝이 있다"는 최소 구조만 검증함 (실제 방 개수/구조는 아직 미확정,
  상점/선택지 방이 생기면 다시 정해야 함)
- 두 번째 이후 몬스터의 공격/방어 주머니 구성 — 첫 몬스터(공격 2D4 / 방어 1D4 / HP10)만
  확정. 잠정적으로 코드(`combat_test.gd`의 `_monster_config_for_room()`)에 방 번호 기반
  스케일링 공식(공격 주사위 2방마다 +1개, 방어 주사위 3방마다 +1개, HP는 매 방 +3,
  다이스 면 개수는 1~2방 D4 -> 3~4방 D6 -> 5방부터 D8, 2026-09-03에 추가)을 넣어
  "던전이 진행될수록 몬스터가 강해진다"는 최소 구조만 검증함. 실제 곡선이 적당한지는
  사람이 플레이해보고 판단 필요.
